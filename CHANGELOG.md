# Changelog

All notable changes to Knot. Versions follow [Semantic Versioning](https://semver.org);
Knot is experimental (0.x): the document format and options may still change.

## 0.4.0 — 2026-09-27

A first release for external users: write, compute and preview a Typst document
with R and Python, see errors in context, and validate the final document by a
full, strict re-execution. See the [release plan](https://github.com/knot-literate-programming/knot/issues/110);
validated through the release candidates `v0.4.0-rc.1` and `v0.4.0-rc.2`.

### Highlights

- **Errors are visible in the PDF.** Document, option, runtime, configuration and
  interpreter errors are rendered where they occur, in the live preview and the
  final build, and reported in the editor with the same message (#98, #99, #101,
  #102, #103, #104, #111, #132, #133, #136, #142, #152). A document with errors
  still produces a PDF showing them.
- **Validation of the final document**: `knot build --strict --no-snapshots`
  re-executes everything in fresh interpreters and fails on any error (#115).
- **Snapshots** replace `freeze`: interpreter state is saved per chunk so that a
  change re-runs only what follows it, with a per-document, per-language policy
  in the YAML header (#45, #46, #47); snapshots that cannot be reused are
  reported (#116); restores match a complete execution (Python random state
  #119, R package order #120).
- **A live preview that keeps up**: a keystroke costs a few milliseconds whatever
  the snapshot size (#123, #126, #127); a chunk waiting to run keeps its previous
  result, veiled, instead of disappearing (#147, #148); no error flashing while
  an option is being typed (#146).
- **Data for Typst**: `export_data()` in R and Python makes results available to
  Typst as `knot-data`, for tables and figures composed in Typst (#48).
- **A scientific reference example**, Anscombe's quartet in R, Python and Typst,
  with a cross-language check at compilation (#49, #134).

### Added

- `show: replace` for presentation overlays (touying) (#24).
- `align` chunk option, applied to labelled and unlabelled chunks alike (#128).
- `[tools]` in `knot.toml`: interpreters, Typst, Tinymist and formatters per
  project, shared by the CLI and the LSP (#54).
- Warnings for unknown `knot.toml` keys, in the PDF, the CLI and the editor (#121).
- `knot clean` reports what it removes (#52).
- `KNOT_VERSION` in `install.sh`, to install a given release such as a
  pre-release.
- Windows: Python is found as `python3`, `python` or the `py` launcher,
  skipping the Microsoft Store shortcuts (#155).
- VS Code: per-language chunk backgrounds, as theme colors (#140, #141).
- A scripted demo of the live preview, regenerated by `demo/record.py` (#149).

### Changed

- Labels and captions: `code-chunk` receives `label` and `caption` and creates the
  figure itself; custom renderers must keep their own `knot-replace` (#33).
- `knot compile` writes a self-contained `.typ` for one file (#114).
- `knot watch` watches the configuration, the sources and their `depends:`
  files, with debouncing (#122).
- In the editor, the Tinymist bundled with the VS Code extension is preferred to
  one found on `PATH` (#139).
- Building from source requires Rust 1.92 (#129) and, for the extension, Node 22
  (#145).

### Fixed

- Many preview, cache and navigation issues: stale compilations no longer publish
  (#38), cached state is isolated and validated (#36), source navigation is
  stable (#39), `_knot_files/` artefacts are always refreshed (#26), sync after
  `knot clean` (#28), automatic cache invalidation when the helper scripts
  change (#29).
- Runtime text is escaped in the generated Typst (#93); error blocks need no
  codly (#94); long inline results are truncated on character boundaries (#92).
- The interpreter startup is not limited by the chunk timeout (#106); the LSP uses
  the project's interpreters for hover and completion (#105).
- Formatting (Air, Ruff, embedded Typstyle) is shared by the CLI and the LSP and
  reliable (#40, #42, #43).
- Typst errors in included files reach the editor (#142); no false errors for the
  library's names or on chunk fences (#144, #150).
- Documentation brought in line with the current behaviour (#129, #134).
- Installation, found by the install smoke test (#154): `install.sh` downloads
  the right archive and verifies its checksum (it could not install on macOS or
  Linux), and `knot-lsp --version` prints its version (#157).

### Compatibility notes

- **`freeze` is removed.** It is now an unknown option (warning, ignored). Use the
  document's YAML header to choose snapshots per language:
  `snapshots: {python: false}` (#46).
- **Labels go in the fence header** (`` ```{r my-label} ``); captions use
  `#| caption:` (#33).
- **The `[helpers]` section of `knot.toml` is no longer used**: remove it (a
  warning says so).
- **Caches are rebuilt** on first use (format changes); `knot clean` removes old
  files.
- **R**: Knot's helpers need the packages `jsonlite` (every chunk), `digest` and
  `svglite` (figures, tables, exports). Without `jsonlite`, the R interpreter
  does not start and the PDF says why (#136).
- **Windows**: the installers are `knot-cli-installer.ps1` and
  `knot-lsp-installer.ps1` (the documented `knot-installer.ps1` never existed).
- Custom `code-chunk` overrides receive new state arguments (`is-stale`); accept
  `..args` to stay compatible.

### Known limitations

See [Status and limitations](README.md#status-and-limitations) and the remaining
items of #96: output capture is explicit (`typst()`, `base_plot()`,
`current_plot()`) and a chunk shows at most one plot and one table (#78, #82,
#83); data frames render as plain tables (#84); snapshots do not pin the
environment; R and Python only, PDF output only, VS Code only.
